# VHM Matching Policy

**Редакция 2.1 · канонический регламент VHM Core.** Пилотный Matcher использует `policy/vi.json` версии 1.1.0. Новый конфиг проходит отдельное согласование. При расхождении исторических документов с этим регламентом для будущего Core применяется этот регламент. Метрики сохраняют протокол своей исторической серии.

## 1. Приём заявки

Excel, CSV и структурированный текст приводятся к неизменяемому снимку заявки. Каждая товарная строка получает стабильный ключ и сохраняет исходный номер, лист или раздел, физическую строку, полное наименование, количество, единицу, примечания и товарную группу. Пропуски, нечитаемые ячейки и ошибки формул отражаются в контроле. Заголовки, итоги и вспомогательные материалы не считаются товарами. Дубликаты строк сохраняются. Одно доказательство поиска можно переиспользовать при идентичном нормализованном ТЗ. Ссылки между строками сверяются по исходным номерам.

## 2. Нормализация

Разделяй бренд, модель и суффикс, серию, заводской артикул, код ВИ и site ID. Не типизируй число по длине. Неизвестный тип идентификатора отправляй в текстовый поиск. Сохраняй исходный токен при исправлении написания. Выделяй назначение, размеры с семантикой и единицами, материал, стандарты, совместимость, комплектность и упаковку. Длина, рабочая длина, диаметр и раскрытие губок сравниваются раздельно. Конфликт серии, суффикса, платформы или артикула требует доказательства эквивалентности. Если критический параметр нельзя вывести из ТЗ, запиши конкретный вопрос.

## 3. Строгая приёмка

Сначала обрабатываются все строки без замены товаров аналогами. Поиск выдаёт кандидатов. Карточка ВИ проверяется через MCP, затем существующий deterministic Matcher принимает решение по подтверждённым требованиям. Название, найденный URL и наличие сами по себе недостаточны. Обязательные характеристики, бренд, модель, артикул, совместимость и комплектность имеют отдельные доказательства. Для заданного бренда поиск по параметрам сохраняет бренд даже без артикула. Ссылка из заявки проверяется против исходного ТЗ. У спорных результатов сохраняются причины и исходные карточки.

Для открытого ТЗ с достаточными безопасными параметрами допускается проверенное предложение с названием, моделью и явными допущениями. Оно имеет отдельный статус и не увеличивает счётчик EXACT. При пробеле, влияющем на безопасность или совместимость, запрашивается уточнение.

## 4. Маршруты и восстановление поиска

| Маршрут | Шаги |
|---|---|
| A | Web First → MCP Verify → deterministic acceptance |
| B | MCP First → deterministic verification и acceptance |
| C | MCP → Web Recovery при отсутствии подтверждённого результата → MCP Verify → deterministic acceptance |

Победитель **UNDECIDED**. C показал лучший наблюдаемый охват выборки. Исторические A/B/C из раннего пилота имели другие определения. Сравнивай только серии с явно зафиксированным протоколом.

Восстановление использует доступные варианты «бренд + модель», заводской артикул, «бренд + артикул», нормализованное имя, обязательные параметры, поиск по каталогу ВИ, внешний поиск по домену ВИ и авторизованный Яндекс. Идентификатор известного типа допускает точечный поиск. Кандидаты объединяются по проверенному site ID, история каналов сохраняется. Любой кандидат, включая найденный вебом, проходит MCP-проверку до строгой приёмки. Яндекс указывай отдельным каналом только при фактическом использовании. При бюджете 0 ₽ платный поиск исключён.

Перед вызовами соблюдай актуальный MCP preflight и лимиты провайдера. При отказе или ограничении фиксируй статус канала. CAPTCHA, 401, 403, 429 и требования авторизации не обходятся. Внешние запросы содержат только товарные признаки. Храни запрос, канал, время, регион, результат, источник подтверждения, ограничения и причины исключения. Различай пустую выдачу, ошибки и отсутствие подтверждения.

## 5. Коммерческие предпочтения

Inforce, Gigant, AEG, Ryobi, KEYANG, Grizzly, ATLET, KENDO, DCA. Tiyang хранится отдельным неподтверждённым обозначением. Приоритет применяется после технической проверки к открытым предложениям и аналогам в согласованных строках. Приоритет не изменяет исходное требование к бренду или статус соответствия. VMT используется только при наличии утверждённого внутреннего источника.

## 6. Количество, наличие и доставка

Храни отдельно запрошенное количество и единицу, единицу продажи, содержимое упаковки, минимальную кратность, количество к заказу, излишек, наличие и подтверждение доставки. Округление вверх выполняется только при известной фасовке и допустимости излишка. Требование ровно указанного количества сохраняется, конфликт выносится на согласование. Источники цен и складских данных привязываются ко времени и региону. `in_stock` не подтверждает доставку нужного количества. Неподтверждённые поля остаются неизвестными. Самовывоз имеет отдельный статус.

Контракт действующего Matcher 1.1.0 использует `pack.size`, `sourceUnit`, `orderUnit` и `ref`. Если источник подтверждает кратность продажи, запиши её целым положительным числом в `pack.orderMultiple` под той же ссылкой. Для ранее сохранённых записей отсутствие поля сохраняет расчёт по одной единице заказа. Явное требование точного количества из структурированной заявки передаётся как `exactQuantity: true`. Результат `quantityVerification` различает `VERIFIED`, `NOT_VERIFIED` и `EXACT_QUANTITY_CONFLICT`. При конфликте показывается минимальное число единиц заказа и излишек в исходной единице, количество к закупке остаётся пустым.

## 7. Согласование

После выдачи строгого результата, если остались строки на возможную замену, один раз спроси «По ненайденным позициям рассматриваем аналоги или строго по заявке?». Решение привязывается к заявке, снимку и ключам разрешённых строк. При разрешении запускается отдельный проход аналогов с проверкой технического допуска и описанием отличий. Разрешение искать аналог и утверждение его конкретного SKU фиксируются отдельно.

## 8. Выдача и контроль

Excel включает «Основной подбор», «Аналоги», «Для клиента», «Контроль». Все исходные строки имеют явный результат или причину отсутствия результата. Для закупки применяй формат `Код ВИ — полное наименование — 30 шт`. Для VI Hunter применяй `Наименование товара 30 шт`. Строки с неизвестным количеством к заказу и несогласованные замены исключаются из подтверждённой закупочной выдачи. Проверяй полноту строк отдельно от точности SKU, фасовки, доставки и цели 95% корректно обработанных строк.
