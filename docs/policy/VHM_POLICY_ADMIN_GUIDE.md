# Управление черновой политикой VHM

Исполняемая политика пилота хранится в `policy/vi.json`. Черновик `config/vhm-policy.yaml` загружается отдельной командой. Он записан в JSON-подмножестве YAML 1.2 для проверки на штатном Node.js. Сохраняйте JSON-синтаксис при редактировании. Схема `schemas/vhm-policy.schema.json` использует Draft 2020-12. Локальная команда проверяет используемые в ней ключевые слова и дополнительные семантические ограничения.

| Область | Кто готовит и проверяет | Ограничения |
|---|---|---|
| Маршруты, глубина, бюджет вызовов, тайм-аут | Оператор предлагает, владелец утверждает | Сначала поиск, потом MCP Verify и детерминированная приёмка. Квоты коннектора действуют независимо |
| Технические инварианты | Разработчик и QA | Верификация карточки и два вида согласия для аналогов защищены схемой |
| Приоритеты брендов | Владелец процесса | Только канонические ID, только открытое ТЗ или разрешённые аналоги. Tiyang остаётся неподтверждённым обозначением |
| Возможности и безопасность | Администратор интеграций | Доступность учтена только в Codex. Яндекс, прямой поиск на сайте и серверный MCP требуют отдельных подтверждений. Учётные данные находятся на стороне хоста |
| Версии | Автор и независимый владелец | Новая ревизия с родительской ссылкой. Утверждение содержит автора проверки, ссылку на свидетельство и хеш содержимого |

## Локальные команды

```sh
node src/policy-draft.mjs validate config/vhm-policy.yaml
node src/policy-draft.mjs dry-run config/vhm-policy.yaml
node src/policy-draft.mjs diff config/vhm-policy.yaml runs/policy/proposed.yaml
node src/policy-draft.mjs rollback-plan runs/policy/current.yaml runs/policy/previous.yaml
node --test
```

Dry-run проверяет форму, допустимость порядка действий и минимальный бюджет на шаги маршрута, выводит хеш и параметры. Сетевой replay и сравнение качества на Golden Set остаются отдельным gate E03.6. Diff выводит изменения по путям и хеши обеих версий. Вывод можно приложить к review. Все команды доступны на чтение и записывают только в стандартный вывод.

Для ревизии, подготовленной к review, используйте статус `validated`, затем зафиксируйте хеш из validate и сохраните результаты QA. Утверждённый снимок использует `approved`, `reviewerId`, `evidenceRef` и `approvedContentHash`. Хеш включает ревизию, автора и родителя. Он стабилен при изменении порядка полей и при записи метаданных утверждения. Инструмент проверяет структуру и совпадение хеша. Подлинность рецензента подтверждается через защищённый review в GitHub.

Rollback-plan принимает две проверенные утверждённые ревизии и требует, чтобы цель была родительской. Команда печатает обратный diff и оставляет решение об активации владельцу. Храните ревизии в Git. Для будущего runtime включение и откат потребуют атомарного переключения указателя утверждённой ревизии после review. До закрытия E03.6 черновик используется только для локальной проверки.
