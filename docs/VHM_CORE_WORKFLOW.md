# Программный вход Excel и маршрут Core

`src/intake-xlsx.mjs` читает .xlsx через bundled `@oai/artifact-tool`. Мэппинг задаёт исходные листы, физические диапазоны и колонки. Для невыбранных листов сохраняется UNMAPPED_WORKSHEET. Заголовки и итоги исключаются явным диапазоном либо skipRows, исключения попадают в контроль. Ошибка формулы фиксируется как неизвестное значение. Строка с данными без читаемого наименования останавливает импорт для проверки карты.

Пример карты для исследованного листа. Остальные листы требуют своей карты либо проверки замечаний.

```json
{
  "requestId": "request-001",
  "policyVersion": "1.1.0",
  "sheets": [{
    "name": "Лист1",
    "firstRow": 1,
    "lastRow": 139,
    "columns": {"number":"A", "text":"B", "unit":"C", "quantity":"D", "notes":"E"}
  }]
}
```

Получить bundled runtime через Codex Workspace Dependencies. В отдельном writable каталоге создать node_modules junction на bundled packages, скопировать туда `intake.mjs` и `intake-xlsx.mjs` и запустить bundled Node с абсолютными путями:

```sh
node intake-xlsx.mjs input.xlsx mapping.json intake.json
```

Снимок создаётся с запретом перезаписи. Код сохраняет исходные значения до нормализации. Модель, артикул, категория и требования передаются явными полями. Автоматическое извлечение этих данных из свободного текста остаётся открытой частью нормализации.

## Контракт исполнения

`runStrictWorkflow` из `src/workflow.mjs` получает существующую runtime policy, snapshot, A/B/C, лимит вызовов, timeout и candidateDepth. Он вызывает проверенные адаптеры последовательно и передаёт решение существующему `match`. Настройки являются параметрами тестового workflow. Новый draft Policy Engine сам по себе их не активирует.

- `searchMcp({query, city, limit, signal})` и `searchWeb` возвращают массив локаторов карточек. Неподходящие домены исключаются. Прямой lookup использует только явно типизированные поля снимка.
- `verifyMcp({candidates, requirements, city, limit, signal})` возвращает карточки в контракте Matcher со ссылкой на сохранённый ответ и проверяемыми checks. Адаптер отвечает за преобразование сырых полей MCP. Карточка должна соответствовать запрошенному локатору.
- Результат содержит intake, evidence и result. Состояние и документы сохраняет вызывающий процесс. После строгой выдачи result.approvalNeeded содержит ключи строк для согласования. Поиск аналогов остаётся отдельным проходом.
- При неполной технической разметке строка получает уточнение. Ошибка или ограничение источника сохраняется и останавливает его повторные вызовы в текущем запуске. Веб-добор выполняется в пределах бюджета.

## Проверенные результаты

Реальный .xlsx прочитан с отображением 139/139 товарных строк в базовом листе. Исходные номера, текст, количество и единица совпали с ранее сохранённым корпусом. Сохранены замечания о шести остальных листах.

Интеграционный replay использовал 30 ранее размеченных требований и архивные ответы C. Результат сохраняет все 139 строк, 11 EXACT и одно открытое предложение. Для остальных строк статус отражает отсутствие достаточной разметки или доказательств. Четырёхлистный Excel экспортирован и проверен по XML, основной лист содержит 139 записей. Этот результат проверяет соединение программных компонентов на исторических ответах. Он не является новым живым замером качества поиска.

20 автоматических тестов проверяют вход, поиск, восстановление, приёмку и ограничения. Серверный доступ к реальным источникам и полный автоматический разбор Excel до технического ТЗ требуют отдельной интеграции.
